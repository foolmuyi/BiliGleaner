## 简介

BiliGleaner 是一个面向 Chrome / Edge 的 B 站浏览器扩展。它不会替你“自动关注”，而是把你最近看过、但尚未关注的 UP 主整理成一个更轻量的追踪池，再定期检查这些 UP 主是否有新视频发布。

这个工具适合下面几类场景：

- 你经常刷到一些有意思的 UP，但不想立刻点关注
- 你想把“正式关注”和“轻度留意”分开管理
- 你希望只基于自己最近一段时间的观看行为建立追踪列表

默认扫描范围为 **最近 7 天**，并且可以在扩展内切换为 30 / 60 / 90 天。

## 核心能力

### 1. 基于历史记录建立追踪池

- 首次使用时可手动扫描最近一段时间的 B 站观看历史
- 只保留视频类历史记录，按观看时间提取对应 UP 主
- 默认扫描最近 **7 天**
- 支持后续增量扫描自上次成功扫描以来新增的历史，持续补充追踪池

### 2. 自动排除你已经关注的 UP 主

- 拉取并缓存当前账号的关注列表
- 扫描结果会自动过滤已关注对象
- 刷新关注缓存后，会自动把这些已关注对象从追踪池和视频动态里清理掉
- 支持手动输入 UID 或空间链接，直接把某个 UP 主加入追踪池

### 3. 黑名单、手动追踪与数据备份

- 可把某些 UP 主加入黑名单，之后即使再次出现在历史记录中也不会被自动追踪
- 黑名单中的 UP 主不能被手动重复加入，避免用户显式配置互相冲突
- 支持导出/导入 **手动追踪列表 + 黑名单**
- 自动扫描发现的 UP 主和视频动态不导出，避免导入过期状态

### 4. 逐个视频检查更新

- 定期轮询追踪池中每位 UP 主的最新投稿
- 以 **单个视频** 为粒度记录更新，而不是只保留“某位 UP 有更新”这一条粗粒度状态
- 保留已读状态，不会因为已读就把视频直接从列表中移除
- 支持在“全部动态”和“仅未读动态”之间切换筛选
- 点击视频时会自动标记为已读
- 对高产 UP 会自动继续翻页，避免因为只检查第一页而漏掉新视频

### 5. 轻量、克制、尽量不打扰

- 所有数据仅存储在浏览器本地 IndexedDB
- 没有 content script，不会向网页注入脚本
- 网络访问仅限 B 站相关域名
- UI 专注在“追踪 / 浏览 / 处理更新”，不做额外社交功能

## 工作方式

1. 扩展扫描你的 B 站观看历史，提取最近看过的视频作者
2. 自动剔除你已经关注的账号
3. 将剩余 UP 主存入本地追踪列表
4. 定期检查这些 UP 主是否发布了新视频，并在弹窗中展示

## 安装

1. 下载或克隆本仓库到本地
2. 打开浏览器扩展管理页
   - Chrome: `chrome://extensions/`
   - Edge: `edge://extensions/`
3. 打开 **开发者模式**
4. 选择 **加载已解压的扩展程序**
5. 选中本项目根目录（包含 `manifest.json`）

使用前请确保你已经在浏览器里登录 B 站账号。

## 使用

### 首次使用

1. 点击扩展图标打开弹窗
2. 确认顶部显示了当前登录的 B 站账号
3. 如需先导入手动追踪列表或黑名单，可先在“控制中心”完成导入
4. 在“追踪列表”页手动点击 **扫描历史** 建立初始追踪池
5. 如果在首次扫描前直接点击 **检查视频更新**，扩展会先自动补做首次扫描
6. 扫描完成后，在“视频动态”页点击 **检查视频更新**

### 日常使用

- 完成首次扫描后，后台会从**最近一次成功历史扫描时间**开始计时，满 **6 小时**后进行下一次增量扫描；浏览器启动或打开弹窗时也会补做一次超时检查
- 后台每 **1 小时**进行一次视频更新检查
- 后台每 **12 小时**刷新一次关注列表缓存；如果扫描时发现缓存已超过 **6 小时**，也会先顺带刷新
- 有未读动态时，扩展图标会显示角标数字

### 支持的操作

| 操作 | 说明 |
| --- | --- |
| 一键关注 | 直接调用 B 站接口关注该 UP 主，并从追踪列表移除 |
| 不再追踪 | 从追踪列表移除该 UP 主，并清理对应视频动态 |
| 拉黑 | 将该 UP 主加入黑名单，并同时移出追踪列表与视频动态 |
| 标记已读 | 将单条视频动态标记为已读，但保留在列表中 |
| 标为未读 | 将已读视频恢复为未读状态 |
| 全部标为已读 | 批量清除未读状态，不删除记录 |
| 动态筛选 | 在“全部”与“仅未读”之间切换当前视频动态列表 |
| 手动追踪 | 在管理页输入 UID 或空间链接，手动加入追踪池 |
| 数据备份 | 导入/导出手动追踪列表与黑名单 |

## 权限与安全

本项目对扩展权限做了尽量收敛的处理，目标是在浏览器中访问其他站点时，尽量避免产生额外的信息暴露面。

### 权限用途

| 权限 | 用途 |
| --- | --- |
| `alarms` | 周期性执行扫描、更新检查、关注缓存刷新 |
| `cookies` | 读取 B 站 `bili_jct`，用于“一键关注”的 CSRF 校验 |

### Host Permissions

- `https://www.bilibili.com/*`
- `https://api.bilibili.com/*`

### 安全边界

- 没有 content script，不会读取当前网页 DOM
- 不会向第三方服务器上传浏览历史、追踪列表或账号信息
- 数据保存在本地 IndexedDB 中，卸载扩展后会被清除
- 导入得到的头像 / 封面 URL 仅接受 B 站相关域名，其他地址会回退为本地占位图
- 所有 `_blank` 链接都带有 `rel="noopener noreferrer"`
- 仓库中不包含 `.env`、私钥、证书、数据库或其他本地敏感文件

## 风控与频率限制

B 站接口存在风控限制，过快请求可能触发 **HTTP 412**。当前实现已经做了节流：

- 历史扫描翻页间隔：**3 ~ 6 秒**
- 视频更新检查间隔：**3 ~ 6 秒**
- 关注列表翻页间隔：**2 秒**
- 历史扫描触发风控后暂停：**30 秒**
- 更新检查触发风控后暂停：**60 秒**

即便如此，如果追踪池规模很大，完整扫描或更新检查仍然可能比较慢。这是有意为之，优先保证稳定性而不是速度。

## 技术说明

### 技术栈

- Chrome Extension Manifest V3
- ES Modules
- IndexedDB
- 原生 JavaScript，无构建步骤

### 存储结构

| Store | 说明 |
| --- | --- |
| `tracking` | 当前追踪中的 UP 主列表 |
| `followed` | 已关注 UP 主缓存 |
| `settings` | 扩展设置 |
| `updates` | 视频动态列表（逐视频记录） |
| `blacklist` | 永久排除的 UP 主列表 |

### 关键实现

- 历史记录通过 `/x/web-interface/history/cursor` 进行游标分页抓取
- 视频投稿通过 `/x/space/wbi/arc/search` 获取，并使用 WBI 签名
- 后台调度统一放在 `background/service-worker.js`
- B 站 API 请求与存储操作都在 Service Worker 中完成；Popup 仅渲染经校验的 B 站图片地址并负责打开链接

## 调试

1. 打开 `chrome://extensions/`
2. 找到 BiliGleaner
3. 进入 Service Worker 调试控制台查看后台日志
4. 右键扩展弹窗，选择“检查”查看弹窗日志

日志统一带有 `[BiliGleaner]` 前缀，便于过滤。

## 已知限制

- WBI 签名依赖 B 站当前实现，若站方改动签名逻辑，需要同步更新
- 关注列表接口存在分页限制，关注数量极大时，过滤结果可能不完全
- 浏览器可能挂起 Service Worker，定时任务依赖 `chrome.alarms` 恢复执行
